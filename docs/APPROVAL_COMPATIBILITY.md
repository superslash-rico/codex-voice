# Computer Use 应用授权提醒

发布版本：0.9.2-approval.1，内部构建号38。安装包沿用已经本机实测的同一构建。

## 为什么原来会漏

现有观察器通过 PermissionRequest 接收普通工具审批，并依据实际审批者过滤自动审核。Computer Use 的“允许 ChatGPT 使用某个应用”属于 MCP 应用确认流程，不能把它等同于普通命令审批。当前本地轮次记录不完整保存这张客户端确认卡片。

## 兼容识别

提醒设置中新增“Computer Use 授权提醒”，默认关闭。用户明确启用并授予辅助功能权限后，只读识别 Codex 当前窗口中的真实应用授权卡片。必须同时存在已知授权问句、实际允许按钮和拒绝按钮；单独的聊天文字或工具运行时长不会触发。

识别在后台工作线程执行，限定遍历和等待时间，跳过输入框和安全输入框。仅提取被授权的应用名及卡片存续，不保存聊天正文或截图，不激活 Codex，也不点击审批。诊断文件只记录开关、状态与数量。

出现的卡片沿用原有“等待审批”声音、电脑/工牌输出、次数、暂停和免打扰设置。延迟3秒播报，处理掉的短暂提示尽量不打扰。点击“已接手”只停止提醒，不代表同意应用权限。卡片离开当前界面并连续两次确认后清除；读取失败时保留短暂宽限，超过15秒失去证据则停止。界面来源的提醒不在应用重启后恢复为历史待审批，而由当前可见卡片重新建立。

## 使用与边界

1. 打开提醒设置，开启“Computer Use 授权提醒”。
2. “输入与识别权限”打开系统辅助功能/设备控制和数据访问设置。临时签名更新后可能需要移除旧项并重新添加当前同名应用。
3. 保留 Codex 中实际授权卡片数秒，随后在原界面自行允许或拒绝。

当前覆盖 Codex 已打开窗口中的应用授权卡片，不保证未展开的后台聊天、其他客户端或未来界面版本。普通命令审批仍走原有事件路径，自动审批过滤保持不变。没有卡片时不把普通长工具调用误判为待审批。

## 验证

199项 Python 测试、原生卡片匹配/生命周期测试及已有协议/音频/宠物/剪贴板测试通过。生产双架构构建、签名、移动路径和隔离配置检查通过。

已在本机用真实计算器访问授权验证：卡片被识别，审批声音开始播放，用户确认“听到了审批语音提醒”，随后已接手且卡片消失。原提醒设置、扬声器、免打扰与登录自启保留；工牌固件未更改。
